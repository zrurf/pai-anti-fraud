# 技术文档

本文档是系统的唯一权威技术说明：架构、模型、数据、训练、评估、部署与完整复现步骤。数据集来源与许可证见 [DATASETS.md](../DATASETS.md)（仓库根目录），实验数字明细见 [results/对比测试报告.md](../results/对比测试报告.md)。

## 1. 系统概述

对中文消息（短信 / 对话 / 邮件）做四分类：**0=正常，1=推销，2=刷单，3=钓鱼**。

方法：MacBERT backbone + DoRA 参数高效微调（可切 LoRA / 全量微调），核心是**输出级 Mixture-of-Experts**——4 个异构专家（各自池化策略、各自负责类别损失加权 λ=3）+ 可训练门控路由器软融合。三阶段训练（Branch–Adapt–Route），ONNX 单图部署，配套 token 级归因解释。

主结果（test n=28,366，种子 42）：完整系统 Macro-F1 **0.8835**（95% CI [0.846, 0.909]），显著优于 DoRA 单头 0.7998（McNemar p≈3.7e-37）与 TF-IDF+LR 基线 0.6609。

## 2. 总体架构

### 2.1 设计要点

- **MoE 放在输出融合层，不插入 BERT 中间层**。中间层插入存在三个已确认的问题：token 级路由在训练初期震荡、部分层路由塌缩导致梯度消失、替换预训练 FFN 破坏已有表示。输出层融合对完整消息语义做专家分工，规避全部三点。
- **专家按诈骗类型分工**：专家 i 对自己负责的类别施加损失加权 λ=3（`experts[].self_class` 显式绑定，与配置列表顺序无关），同时用全量四类数据训练以输出完整 C 维分数。
- **异构性**体现在三处：池化策略（mean / attention / cls / mean_max）、MLP 结构（hidden 与层数）、阶段二的数据侧重（负责类别约 3 倍过采样 + 各自的数据增强组合）。

### 2.2 数学形式化

设 backbone 输出 token 级表示 $H$（[batch, seq, 768]）：

$$z_i = E_i(p_i(H)),\ i=1..4 \qquad g = \mathrm{softmax}(\mathrm{router}([\mathrm{mean}(H); \mathrm{max}(H)])) \qquad z = \sum_i g_i \cdot z_i$$

- $E_i$：专家 i 的 MLP 头；$p_i$：该专家的池化算子；
- 路由器 = 线性投影 + 2 层 MLP + softmax，**温度固定为 1**（不引入温度调度：其调控目标与负载均衡损失重叠，统一由 α 控制，超参更少）；
- 融合 logits $z$ 过 softmax 得类别概率。

### 2.3 专家配置（configs/default.yaml）

| 专家 | pooling | hidden | layers | 负责类别 | 阶段二增强 |
| :--- | :--- | ---: | ---: | :--- | :--- |
| 推销 | mean | 512 | 2 | 1 | emoji_insert |
| 刷单 | attention | 256 | 3 | 2 | — |
| 钓鱼 | cls | 512 | 2 | 3 | — |
| 正常 | mean_max | 256 | 2 | 0 | — |

backbone：`hfl/chinese-macbert-base`（本地副本 `models/chinese-macbert-base/`，加载时自动优先使用本地目录）。PEFT：DoRA，r=8、alpha=16、dropout=0.1、target=[query, key, value]（约 47 万可训练参数，占全模型 0.46%）。

## 3. 损失与训练策略

### 3.1 损失

- **加权交叉熵**：全局类别权重 $w_c$（`class_weights: auto` = 训练集频率倒数）× 专家分工权重 $\lambda_{i,y}$（专家 i 对类别 y，$\lambda_{i,i}=3$，其余为 1）。
- **负载均衡损失**（Switch Transformer 形式 $\sum_i f_i \cdot p_i$，系数 α=0.01，全程固定）：f_i 为专家激活比例、p_i 为平均门控概率；监控两者防路由塌缩。实测最终 f_i=[0.276, 0.152, 0.186, 0.386]，无塌缩。

### 3.2 三阶段 Branch–Adapt–Route

| 阶段 | 内容 | 可训练参数 | 配置 |
| :--- | :--- | :--- | :--- |
| 0（可选） | MLM 继续预训练：80 万短信语料采样 200k，2 epoch，lr 5e-5，掩码率 0.15 | backbone（含 DoRA） | `stage1_finetune --task mlm` |
| 1 Branch | 四分类单头微调（均值池化 + Linear），3 epoch，lr 2e-5，batch 32；**该单头即对比基线"MacBERT+PEFT 单头"** | backbone（含 DoRA）+ 单头 | `--task clf --init-from <mlm>` |
| 2 Adapt | 冻结 backbone（eval 模式，无 dropout 泄漏），逐个训练 4 专家，4 epoch，lr 1e-3，batch 64，WeightedRandomSampler 按负责类别 3 倍过采样 | 仅当前专家 | `stage2_experts` |
| 3 Route | 冻结 backbone 与全部专家，训练路由器 6 epoch（lr 1e-3）；随后联合微调 2 epoch（lr 5e-4）：解冻路由器 + 各专家池化与 MLP（attention 池化的 query 随之解冻），backbone 仍冻结 | 路由器（→ 路由器+专家模块） | `stage3_router --joint` |

每 epoch 按 val Macro-F1 保存 best（`model.pt`）；`last*.pt` 为断点续训状态（含 optimizer/scheduler/epoch）。续训：原命令加 `--resume <out目录>`（stage2 逐专家跳过已完成者；`--epochs` 需 ≥ 已完成 epoch 数）。

### 3.3 超参唯一来源

`configs/default.yaml`（种子、PEFT、专家表、损失、各阶段 epoch/lr/batch、服务端口）。变体配置：`configs/stage1_lora.yaml`（LoRA 对照）、`configs/seed_*.yaml`（多种子，仅 seed 字段不同；数据划分不随种子变化）。

## 4. 数据

四分类训练池 327,232 条（train 270,471 / val 28,395 / test 28,366），分层划分（种子 42）：

| 类别 | 样本量 | 主要来源 |
| :--- | ---: | :--- |
| 正常 | 160,330 | FGRC-SCD 无风险、天池 label00（运营商营销=近领域负样本）、TeleAntiFraud 正常通话转写、spam10000 闲聊、LLMGen 中文正常邮件 |
| 推销 | 53,939 | CCL2023 虚假购物服务、FGRC-SCD 虚假购物服务、FBS_SMS AD_*、spam10000 群聊推广 |
| 刷单 | 28,492 | CCL2023 刷单返利类 28,353（受害人笔录文体）+ anti_fraud 兼职刷单对话 139 |
| 钓鱼 | 84,471 | 天池/FGRC-SCD/CCL2023 冒充类、TeleAntiFraud 冒充通话、LLMGen/PhishMMF 中文钓鱼邮件、FBS FR_Phishing |

已知局限（解读结果时必须一并考虑）：

1. **刷单类 val/test 各仅 14 条**（CCL2023 只有官方 train 文件），该类测试指标统计上脆弱；
2. 刷单训练主体为受害人笔录，与消息文体存在域偏移——校园风格刷单话术可能被判为"推销"；
3. 钓鱼↔推销是主要混淆轴（两类在消息文体下边界天然模糊）。

TeleAntiFraud 的 13,711 条通话经说话人分离转写（paraformer-zh + fsmn-vad + ct-punc + cam++）+ PII 脱敏（正则 + CLUENER NER）后入库。完整来源、许可证、引用义务见 [DATASETS.md](../DATASETS.md)。

## 5. 评估

- **指标**：Accuracy、Macro-F1、按类 Precision/Recall/F1、混淆矩阵、ECE（10 bins）、Macro-F1 bootstrap 95% CI（1,000 次重采样）；同 test 集两模型比较用 McNemar 检验 + 配对 bootstrap Macro-F1 差值。
- **工具**：`scripts/eval_testset.py`（`--compare` 出统计检验；`--fusion equal|top1` 做融合方式消融）。
- **公平性**：所有方案同输入（纯文本）、同划分、同 tokenizer；报告置信区间与显著性检验而非单次最优。
- **主结果**（详见对比测试报告）：MoE 0.8835 [0.846, 0.909] > DoRA 单头 0.7998 [0.745, 0.843] ≈ LoRA 单头 0.7953 [0.742, 0.838] >> TF-IDF+LR 0.6609。McNemar 均显著（p<1e-35）。
- **融合消融**：门控 0.8835 ≈ 等权 0.8827（噪声内）>> top-1 硬选择 0.8076（-7.6 点且 ECE 恶化）。结论：增益来自多专家互补表示 + 软融合；路由器当前价值在软融合与可解释性，非异于等权的动态路由。
- **token 级归因**：`/explain` 提供 Occlusion 留一法归因（见 §6.3）。

## 6. 部署

### 6.1 ONNX 导出

`scripts.export_onnx` 加载 stage3 checkpoint → PEFT 权重合并进底座 → 单图导出。输入 `input_ids`/`attention_mask`，输出 `logits`/`gate`/`expert_logits`（含注意力池化专家时另有 `attn_scores`，为该专家对每个 token 的注意力权重）；`predict_meta.json` 记录类别名、专家名与 attn_expert。导出后新旧图输出逐位一致（已验证 diff=0.0）。部署工件复制到 `release/model/`。

### 6.2 异步 API

服务代码 `antifraud/serving/api.py`（FastAPI）+ `onnx_infer.py`（ONNXRuntime 封装）。**任务式异步协议**：提交请求立即返回 ticket，凭 ticket 轮询结果——归因等重操作不阻塞 HTTP 连接。

| 端点 | 方法 | 说明 |
| :--- | :--- | :--- |
| `/health` | GET | 健康检查 |
| `/predict` | POST | 提交预测任务 `{"text": "..."}` → `{"ticket", "status"}` |
| `/explain` | POST | 提交归因任务 `{"text": "...", "top_k": 8}` → `{"ticket", "status"}` |
| `/tasks/{ticket}` | GET | 查询任务：`queued` / `running` / `done`（含 `result`）/ `failed`（含 `error`） |

结果字段：`label`/`label_name`/`confidence`/`probabilities`/`expert_weights`/`expert_opinions`/`evidence`（关键词快路径证据）；`/explain` 的 result 另含：

- `attribution`：Occlusion 留一法 token 归因。`source="occlusion"` 时含 `tokens`（top-k，中文按字、英文/数字按整词，`drop`=遮蔽后目标类概率下降幅度）与 `merged`（相邻字合并后的词组显示版，如"教务处"）；异常时 `source="keyword_fallback"` 降级；
- `expert_attention`：刷单专家注意力 top-k 词（`gate_weight` 标注该专家权重，低时仅作参考）。

性能（CPU）：/predict ~28ms；/explain 0.4–1.5s（随文本长度）。启动依赖：`onnxruntime fastapi uvicorn transformers numpy`（无需 torch/GPU）。

### 6.3 Token 级归因

实现于 `antifraud/serving/onnx_infer.py`（`attribute_occlusion` / `explain`），方法为 Occlusion 留一法：
按分词器 word 映射分组（中文按字、英文/数字按整词），逐组替换为 `[UNK]`，全部 N+1 副本拼 batch 走现有 ONNX 图
一次前向，分数 = 基线预测概率 − 遮蔽后预测概率。纯 ONNX 实现，不需要梯度/torch，不改预测行为。

- 接口：`POST /explain {"text", "top_k"}` 提交，`GET /tasks/{ticket}` 取结果（见 §6.2）。
- 响应字段：`attribution`（source=occlusion：tokens 带 drop 与字符区间、merged 相邻字合并、baseline_prob、
  目标类别；异常降级 source=keyword_fallback 不阻塞主结果）；`expert_attention`（attn_scores 第二视角，
  携带刷单专家 gate_weight 供判断解释力）。
- 复现验证：`/explain` CPU 均值 1.49s（68 字）/0.4–0.7s（短文本）；钓鱼话术 top 归因="教务处""助学金"
  （删"务"字 P(钓鱼) 0.61→0.21）；正常消息无诈骗词入选。冒烟测试覆盖 TinyTokenizer 降级分支
  （`tests/test_pipeline_smoke.py` 的 check_explain_degrade）。
- 重新导出：`scripts.export_onnx` 自动附加 attn_scores 输出与 `attn_expert` 元数据；重导出图与原图输出
  逐位一致（diff=0.0）。

### 6.4 发布目录

`release/model/`（部署工件）+ `release/README.md`（部署指南）。完整项目离线分发的打包清单见根目录 README。

## 8. 复现步骤

在仓库根目录执行。Python ≥3.12，依赖 `pip install -r requirements.txt`（GPU 训练按 PyTorch 官网装对应 CUDA 版 torch）。离线环境：把 `hfl/chinese-macbert-base` 的模型文件（config.json、pytorch_model.bin、vocab.txt、tokenizer*.json）放入 `models/chinese-macbert-base/`；代码自动本地优先加载，无网可用。

### 8.1 冒烟测试（无需任何数据与权重）

```bash
python -m tests.test_moe_shapes        # 模型/损失形状与梯度
python -m tests.test_pipeline_smoke    # 三阶段 + ONNX + 归因降级端到端
```

### 8.2 数据重建

按 DATASETS.md 获取原始数据放入 `rawdata/`，然后：

```bash
python -m scripts.build_processed      # 解析→映射→去重→分层划分→ data/processed/*.jsonl + dataset/*.lance
```

### 8.3 正式训练（主路径）

```bash
# 阶段 0：MLM 继续预训练
python -m antifraud.training.stage1_finetune --task mlm \
    --corpus "rawdata/SpamMessage-master/data/带标签短信.txt" \
    --out checkpoints/stage1_mlm --max-samples 200000

# 阶段 1：四分类单头微调
python -m antifraud.training.stage1_finetune --task clf \
    --train data/processed/train.jsonl --val data/processed/val.jsonl \
    --out checkpoints/stage1 --init-from checkpoints/stage1_mlm/model.pt

# 阶段 2：四异构专家
python -m antifraud.training.stage2_experts --stage1 checkpoints/stage1/model.pt \
    --train data/processed/train.jsonl --val data/processed/val.jsonl --out checkpoints/stage2

# 阶段 3：路由 + 联合微调
python -m antifraud.training.stage3_router --stage2 checkpoints/stage2/model.pt \
    --train data/processed/train.jsonl --val data/processed/val.jsonl \
    --out checkpoints/stage3 --joint
```

中断后原命令加 `--resume <out目录>` 续训。变体：`--config configs/stage1_lora.yaml`（LoRA 对照，输出另存）；`--config configs/seed_<种子>.yaml`（多种子，输出 `checkpoints/seed_<种子>/...`，命令同上并替换各 --out）。

### 8.4 评估与消融

```bash
python -m antifraud.baselines.tfidf_baseline --train data/processed/train.jsonl \
    --test data/processed/test.jsonl --out results/tfidf_baseline.json     # 传统基线（~2 分钟）
python -m scripts.eval_testset --checkpoint checkpoints/stage1/model.pt --mode stage1 --out results/stage1_test.json
python -m scripts.eval_testset --checkpoint checkpoints/stage3/model.pt --mode stage3 \
    --out results/stage3_test.json --compare checkpoints/stage1/model.pt   # 含 McNemar + 配对 bootstrap
python -m scripts.eval_testset --checkpoint checkpoints/stage3/model.pt --mode stage3 \
    --fusion equal --out results/ablation_a1_equal.json                    # 消融 A1
python -m scripts.eval_testset --checkpoint checkpoints/stage3/model.pt --mode stage3 \
    --fusion top1 --out results/ablation_a2_top1.json                      # 消融 A2
```

### 8.5 导出与部署

```bash
python -m scripts.export_onnx
mkdir -p release/model && cp checkpoints/onnx/{model.onnx,predict_meta.json,tokenizer.json,tokenizer_config.json} release/model/
python -m uvicorn antifraud.serving.api:app --host 0.0.0.0 --port 8000

# 异步流程示例
# curl -X POST localhost:8000/predict -H "Content-Type: application/json" -d '{"text":"..."}'
#   → {"ticket": "...", "status": "queued"}
# curl localhost:8000/tasks/<ticket>   → {"status": "done", "result": {...}}
```

### 8.6 黄金测试集（域偏移预检）

按 `docs/黄金测试集LLM生成Prompt.md` 生成并人工审核后存为 `data/golden_test_set.jsonl`，校验：

```bash
python -m scripts.validate_golden_set.py
python -m scripts.eval_testset --checkpoint <ckpt> --mode <stage1|stage3> \
    --test data/golden_test_set.jsonl --out results/golden_<模型名>.json
```

## 9. 版本控制与离线分发
